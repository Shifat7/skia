Local pre-PR checkpoint

AI wrote the code. Skia helps you understand it before you trust it.

Skia is the missing step between generation and commit for one developer: a short, source-backed reading of a change, one prediction you make yourself, and a visible record of anything the tool could not analyze.

01 — Problem

The hard part is owning the diff, not generating it.

AI coding tools can produce a working-looking change faster than you can build a reliable mental model of it. Skia is aimed at that gap, before the pull request.

Extra machinery

An abstraction, helper, or dependency that the change did not actually need.

Hidden branches

An error path or early return buried inside a large generated diff.

Unfamiliar success

Code that compiles and passes tests while the behavior is still unfamiliar.

Missing production detail

Retries, idempotency, error handling, or observability that the diff never made obvious.

02 — How it works

Read a short view. Predict one result. Then open the source.

This is the intended workflow. skia review and skia repo review are product examples. The shell in src/main.ts is unimplemented.

  1. AI tool Cursor, Claude Code, Codex, or another generator
  2. Diff The change you are about to trust
  3. Skia Simplified view, one prediction, visible gaps
  4. Tests Your existing checks stay authoritative
  5. Commit / PR After you can say what the change does

Hand-written samples, labeled as intended output, are in examples/. The original source and the exact Git snapshot remain authoritative. A simplified view is a reading map, not code to copy and not proof of semantic equivalence.

03 — Capabilities

Foundation in the tree. Review experience still ahead.

In the repository now

Exact Git snapshots

Staged and committed-HEAD snapshots with path-safe local storage.

Parsers and schemas

TypeScript, TSX, and Python analysis, plus schema and coverage validation.

Explicit uncertainty

Outcomes stay labeled supported, partial, unmapped, unsupported, failed, and unchecked.

Documented product, not runnable

Intent as behavior reading

A short view of what the changed code appears to do, with source anchors. It does not prove intent.

One prediction prompt

You answer before feedback. The answer is developer-supplied, not a runtime verdict.

Local-first privacy

No Skia review backend and no product telemetry in the current phase. A future cloud model is opt-in egress.

04 — Install

npm comes first. Nothing is published yet.

The working path today is a clone of this repository. A global install command will appear here only after it succeeds on a clean machine. Node.js 24.x (>=24.0.0 <25) is the engine floor.

Verify the foundation

These commands check snapshots, parsers, schemas, and storage. They do not review a diff.

git clone https://github.com/Shifat7/skia.git
cd skia
npm ci
npm test

npm — available first, still private

package.json is private: true at 0.0.0. Do not install the unrelated skia name already on the npm registry. Publication also waits on the open name decision in OD-1. When a package exists, the command will require Node.js 24.x and will be written here.

Also planned

A Homebrew tap, and a curl or binary installer after the first signed release. Both stay as text until a working command can replace this sentence.

05 — Integrations

Same local reviewer, several hosts. None of the adapters ship yet.

Skia is a local CLI plan. It does not replace Cursor, Claude Code, or Codex. Each row is the job the adapter should do later.

Planned

A project rule that runs skia on a staged diff before commit. Not a Cursor Marketplace extension today.

Planned

Claude Code

A plugin and skill that wrap the same local review. There is no plugin install path yet.

Planned

Codex

A SKILL.md the agent can load. It is not a published skill pack.

Planned

GitHub Actions

A workflow that installs the CLI and can keep an artifact or exit code. Pull-request comment bots are outside the current plan. No action YAML is published here.

06 — Privacy

No Skia backend. Egress only to a model you choose later.

Skia does not operate a review backend and does not send product telemetry. The Phase 1 foundation keeps snapshot and parse artifacts local. A future repository mode may send bounded context to an LLM endpoint you configure, after explicit consent. Pair that mode with a local model when you need the run to stay on the machine. Diffs stay on disk unless you copy them elsewhere.

07 — Limitations

Read this before treating Skia like a hosted reviewer.

Early preview

Package version 0.0.0. The review CLI is a bootstrap shell. Expect the flags to change until 1.0, and expect no 1.0 until the name and publication decision is recorded.

One developer, before the PR

Skia is a local checkpoint. CodeRabbit, Greptile, and Copilot Review remain hosted PR tools. Skia does not claim a catch rate against them.

Advisory reading

A future finding is a suggestion. The implementation plan excludes CI review comments. Tests and the original source stay authoritative.

Model-dependent, when a model is used

Repository drafts would be model_derived. They are not deterministic proof, semantic equivalence, or a verified HLD/LLD.

Languages

Supported source languages are exactly TypeScript, TSX, and Python.

Proof gaps

There is no public benchmark, no captured CLI transcript, and no tester-quote wall. The examples are intended UX. Stars are not used as a quality signal.
