## How it works

`skia review` is a documented name. The shell in `src/main.ts` is unimplemented. Intended loop:

<Steps>

1. Stage or point at a change — exact Git snapshot when the product CLI lands.

2. Read the simplified view. It is a map, and it is not executable.

3. Predict one result yourself, before any feedback.

4. Open original code wherever coverage is `partial`, `unmapped`, `unsupported`, `failed`, or `unchecked`.

</Steps>

## Problem

AI tools can ship a working-looking diff faster than a reliable mental model forms. Extra abstractions, buried branches, and unfamiliar behavior that still passes tests are easy to miss. Skia is the intended checkpoint for one developer before that gap becomes a reviewer's problem.

## FAQ

<div class="faq">
	<details>
		<summary>Is <code>skia review</code> available today?</summary>
		<p>No. The package is private at 0.0.0, and the shell does not run a review. There is no working global npm install, Homebrew formula, or curl installer.</p>
	</details>
	<details>
		<summary>Does my code leave the machine?</summary>
		<p>Foundation work is designed to keep snapshot and parse artifacts local. Skia does not operate a review backend and does not send product telemetry. A future repository mode may send bounded context to an endpoint you configure, after consent. See <a href="/skia/privacy/">Privacy</a>.</p>
	</details>
	<details>
		<summary>Is this a CodeRabbit or Greptile replacement?</summary>
		<p>No. Skia is intended as a local pre-PR comprehension checkpoint for one developer — simplify, predict, surface uncertainty — not a hosted PR bot or agent fix loop.</p>
	</details>
	<details>
		<summary>How do I install it?</summary>
		<p>You do not install a review CLI yet. Contributors run the foundation with Node 24+ from the repository (<a href="/skia/contribute/">Contribute</a>). No <code>npm i -g skia</code> command is published here.</p>
	</details>
	<details>
		<summary>Which languages are analyzed today?</summary>
		<p>Exactly TypeScript, TSX, and Python. Anything else stays <code>unsupported</code>.</p>
	</details>
	<details>
		<summary>Is this Google's Skia?</summary>
		<p>No. Different project. The shared name is an open release risk (<a href="https://github.com/Shifat7/skia/blob/main/docs/OPEN_DECISIONS.md">OD-1</a>), not an affiliation.</p>
	</details>
</div>
