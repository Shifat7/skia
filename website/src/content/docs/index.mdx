## What ships today

Phase 1 foundation is in the repository. The only review command that runs is a narrow `skia review` pilot. Planned items stay on <a href={withBase('/status/')}>Status</a> — they do not get a green check here.

## How it works

`skia review` runs for exactly one staged `.ts` file containing one named function with a strict literal guard and a literal return. The shell in `src/main.ts` is `implemented: "partial"`. `skia repo review` is still planned, as is any simplified view or prediction prompt beyond that pilot. You do the reading. The intended loop:

<Steps>

1. Stage one supported `.ts` file. The pilot captures an exact Git snapshot. Broader inputs stay outside the pilot.

2. Read the simplified view. It is a map. It is not executable.

3. Predict one result yourself, before any feedback.

4. Open original code wherever coverage is `partial`, `unmapped`, `unsupported`, `failed`, or `unchecked`.

</Steps>

## Problem

An AI can write a diff faster than you can understand it. Sending that diff to another model for review does not make the commit yours. Extra abstractions, buried branches, and behavior that still passes tests are easy to miss when you have not read them.

Skia is a local checkpoint for that read. It is for the engineer who stays accountable for what they commit: you read the change, predict one result, and open anything the analysis could not cover. Handing the diff to an AI and shipping without reading it — vibe coding — is the wrong workflow for this tool.

## FAQ

<div class="faq">
	<details>
		<summary>Who is this for?</summary>
		<p>Engineers who review their own changes, including diffs an AI wrote, and who stay accountable for what they commit. You read the change, predict one result, and check the source yourself. It is the wrong tool if you want to hand the diff to a model and ship without reading it.</p>
	</details>
	<details>
		<summary>Is <code>skia review</code> available today?</summary>
		<p>Only as a narrow pilot: one staged <code>.ts</code> file, one named function, a strict literal guard, and a literal return, via <code>node dist/src/main.js review</code> after a build. The package is private at 0.0.0. There is no working global npm install, Homebrew formula, or curl installer. <code>skia repo review</code> does not run.</p>
	</details>
	<details>
		<summary>Does my code leave the machine?</summary>
		<p>Foundation work keeps snapshot and parse artifacts local. Skia does not operate a review backend and does not send product telemetry. A future repository mode may send bounded context to an endpoint you configure, after consent. See <a href={withBase('/privacy/')}>Privacy</a>.</p>
	</details>
	<details>
		<summary>Does Skia review the change for me?</summary>
		<p>No. You read what the change appears to do, you supply the prediction, and you open the original source where coverage is incomplete. Skia does not approve a commit, and it does not post review comments.</p>
	</details>
	<details>
		<summary>How do I install it?</summary>
		<p>You do not install a review CLI yet. Contributors run the foundation with Node 24+ from the repository (<a href={withBase('/contribute/')}>Contribute</a>). No <code>npm i -g skia</code> command is published here.</p>
	</details>
	<details>
		<summary>Which languages are analyzed today?</summary>
		<p>Exactly TypeScript, TSX, and Python. Anything else stays <code>unsupported</code>.</p>
	</details>
	<details>
		<summary>Is this Google's Skia?</summary>
		<p>No. Different project. The shared name is an open release risk (<a href="https://github.com/Shifat7/skia/blob/main/docs/OPEN_DECISIONS.md">OD-1</a>), not an affiliation.</p>
	</details>
</div>
