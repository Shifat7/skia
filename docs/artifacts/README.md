# Proposed Output Reference

> **No outputs exist.** This document defines proposed Phase 0 staged and
> repository artifacts. Examples are contracts to be converted into canonical
> schema fixtures before implementation.

---

## 1. Shared conventions

Every output distinguishes:

- `deterministic` facts computed from a captured Git snapshot;
- `model_derived` claims generated by the configured repository agent;
- `developer_supplied` predictions entered before feedback; and
- `not_available` values with a stable reason.

Raw source remains authoritative. Coverage, exclusions, unsupported regions,
and uncertainty are never hidden by a completed card or generated document.

Timestamps use UTC. Repository bundles use one path-safe basic ISO 8601 run ID,
for example `20260805T001500Z`, in the directory and every filename.

---

## 2. Staged terminal surface

The default surface is collapsed evidence, not the full diff:

```text
calculateFinalPrice                 12 changed lines -> 4 evidence lines

  total <= 0       -> return 0
  active member    -> total * 0.90
  valid promotion  -> subtract promotion amount
  final result     -> clamp at 0, then round

BEHAVIOR CHECK 1/1
Given: total=100, member=active, promotion=10
When:  calculateFinalPrice(total, member, promotion)
Expected return: ___
> 80

Source check: source-derived match for the displayed path

[e] evidence details  [d] original staged diff  [n] next
```

The reducer stores each displayed relation with source anchors and coverage:

```json
{
  "kind": "transformation",
  "relation": "active member -> total * 0.90",
  "source_anchors": [
    {
      "side": "staged",
      "path": "src/pricing/price.ts",
      "start_line": 12,
      "end_line": 12,
      "blob_oid": "f3b4...91aa"
    }
  ],
  "derivation": "deterministic",
  "coverage": "supported",
  "details_available": true
}
```

`relation` is a compact review representation. It is not executable code or
semantic-equivalence proof.

### Unmapped output

```text
WARNING: 7 changed TypeScript lines are unmapped.
Collapsed evidence does not cover imports, a deleted callback, or a compound
stateful branch.

[d] inspect unmapped diff  [s] skip entity  [q] stop
```

Unmapped and unsupported regions stay present in terminal and receipt scope.

## 3. Minimal Behavior Card

The normal staged card is one prediction:

```json
{
  "scenario": {
    "given": {
      "arguments": {
        "total": 100,
        "member": "active",
        "promotion": 10
      },
      "state_note": null
    },
    "when": {
      "entity": "calculateFinalPrice",
      "invocation": "calculateFinalPrice(total, member, promotion)"
    }
  },
  "prediction": {
    "kind": "return_value",
    "value": 80
  },
  "because": null,
  "impact": null,
  "action": "complete"
}
```

- `scenario` is system-supplied.
- `prediction` is developer-supplied before feedback.
- `because` is optional after mismatch, explicit request, or a causal-risk
  prompt.
- `impact` is optional for high-risk or caller-visible prompts.
- A skip stores `action: "skip"` with no fabricated prediction.

### Source check

A narrow path comparison uses exactly:

| Receipt value | Terminal label | Meaning |
|---------------|----------------|---------|
| `source_derived_match` | `source-derived match` | Prediction matches one supported observed path endpoint |
| `source_derived_mismatch` | `source-derived mismatch` | Prediction differs from one supported observed path endpoint |
| `not_checkable` | `not checkable` | Arguments, branch, endpoint, or wider state is outside the safe subset |

None means correct, runtime verified, equivalent, fully covered, or review
passed.

### Probe specification

```json
{
  "status": "draft_unexecuted",
  "invoke": {
    "entity": "calculateFinalPrice",
    "arguments": [100, true, 10]
  },
  "expect": {
    "kind": "return_value",
    "value": 80
  }
}
```

Ineligible cards use `not_available` plus a reason. Probe specifications are
never code, written into the project, executed, or called tests.

## 4. Staged receipt

Proposed path:

```text
.skia/receipts/20260805T001500Z-8f5d1a2c-session.json
```

The normative receipt will be a JSON Schema fixture. At minimum it binds:

- schema/tool version and completion timestamp;
- base commit, branch/detached/unborn state, immutable index identity, ordered
  paths/modes/blob OIDs, and canonical diff hash;
- total, mapped, and unmapped changed TypeScript lines;
- one entity entry per supported prompt;
- collapsed evidence and source anchors;
- system scenario, pre-feedback developer prediction, optional later
  reflection, source-check status, and probe status;
- show-source/show-evidence actions, skips, duration, and errors; and
- privacy and deletion caveats.

`card_status` describes prediction completion only. Coverage is a separate
required object.

## 5. Repository bundle

Proposed command:

```text
skia repo review
```

Proposed local gitignored layout:

```text
.skia/dist/20260805T001500Z/
  repo-hld-20260805T001500Z.md
  repo-lld-20260805T001500Z.md
  repo-collapsed-evidence-20260805T001500Z.md
  repo-behavior-cards-20260805T001500Z.json
  repo-coverage-20260805T001500Z.json
  repo-manifest-20260805T001500Z.json
```

A same-second collision receives a suffix such as
`20260805T001500Z-01`; the resolved run ID is used everywhere.

### 5.1 HLD banner and shape

`repo-hld-<run-id>.md` begins with a disclosure:

```text
Repository architecture draft
Snapshot: c8d1a1885f52b1664a6266900296f1ce0886b715
Coverage: TypeScript-first; see repo-coverage-20260805T001500Z.json
Generation: model_derived via configured agent
Authority: review aid, not maintained architecture or runtime proof
```

The HLD contains only:

- observed packages, entry points, configuration, and external interfaces;
- model-derived subsystem map with claim IDs and confidence;
- major source-anchored control/data flows;
- unresolved architecture questions; and
- unsupported-language/exclusion summary.

It does not contain file-by-file narration.

### 5.2 LLD banner and shape

`repo-lld-<run-id>.md` uses compact tables for packages, modules, exported
declarations, direct dependencies, unresolved edges, and selected subsystem
details. Unselected modules remain indexed but unexpanded to preserve the
reduced-reading objective.

Every generated statement links to a claim ID rather than presenting
unattributed prose.

### 5.3 Collapsed architecture evidence

```text
request route -> application service -> repository adapter -> database
payment result -> order state update -> notification enqueue
configuration -> provider adapter -> bounded agent request
```

Each relation carries observed/model-derived segments separately, source
anchors, confidence, and coverage.

### 5.4 Repository Behavior Cards

Every successful generated bundle includes one architecture card. If the card
cap is greater than one, the developer may select additional subsystems.

```json
{
  "repo_card_cap": 3,
  "cards": [
    {
      "scope": "architecture",
      "subject": "request-to-persistence flow",
      "derivation": "model_derived",
      "scenario": {
        "given": "A valid order request reaches the HTTP entry point",
        "when": "the order is accepted",
        "question": "Which boundary owns the durable state change?"
      },
      "prediction": "repository adapter",
      "source_check": { "status": "not_checkable" },
      "action": "complete"
    },
    {
      "scope": "subsystem",
      "subject": "billing",
      "action": "complete"
    },
    {
      "scope": "subsystem",
      "subject": "persistence",
      "action": "skip"
    }
  ],
  "unchecked_subsystems": ["api", "notifications", "web"]
}
```

A model-generated answer is not ground truth. Repository cards receive a
source check only when the selected path is within the deterministic supported
subset; otherwise they remain ungraded or `not_checkable`.

### 5.5 Coverage artifact

`repo-coverage-<run-id>.json` records every captured tree entry as included,
excluded, unsupported, or failed. It includes:

- scanned TS/TSX files and bytes;
- manifests, configuration, lockfiles, and docs used for structure;
- generated/vendor/fixture/ignored classifications;
- other source-language inventory;
- unsupported modes, encodings, parse regions, and unresolved imports;
- deterministic and model-derived claim counts;
- subsystem candidate, selected, unselected, skipped, and unchecked counts;
- resource-limit and generation failures; and
- arithmetic invariants checked by schema tests.

### 5.6 Manifest

The manifest is the bundle authority:

```json
{
  "schema_version": 1,
  "run_id": "20260805T001500Z",
  "status": "complete",
  "completed_at": "2026-08-05T00:15:00Z",
  "repository": {
    "commit_oid": "c8d1a1885f52b1664a6266900296f1ce0886b715",
    "branch": "main",
    "working_changes_included": false
  },
  "scanner": {
    "tool_version": "0.0.0-proposed",
    "typescript_grammar_version": "to-be-pinned",
    "limits_profile": "phase0-default"
  },
  "generation": {
    "status": "completed",
    "provider": "configured-agent",
    "model": "disclosed-at-runtime",
    "external_egress_consented": true
  },
  "artifacts": [
    {
      "kind": "hld",
      "path": "repo-hld-20260805T001500Z.md",
      "sha256": "4c6d...f921"
    }
  ],
  "coverage_file": "repo-coverage-20260805T001500Z.json",
  "cards_file": "repo-behavior-cards-20260805T001500Z.json",
  "privacy_caveat": "Local bundle may contain sensitive architecture and code-derived claims; inspect and delete when no longer needed."
}
```

The final schema also records effective limits/configuration, every artifact
hash, claim counts, selected/unselected subsystems, completion/card status,
errors, and deletion caveat. HLD and LLD claim IDs resolve through the manifest
to derivation, confidence, anchors, and artifact location.

## 6. Local lifecycle

Proposed commands:

```text
skia runs list
skia runs inspect 20260805T001500Z
skia runs delete 20260805T001500Z
```

Phase 0 has no automatic upload, sharing, tracked export, or team dashboard.
Declining external-agent consent may still produce deterministic coverage and
structural artifacts, with HLD/LLD marked `not_available`.

---

## 7. Explicitly absent

No output is a correctness certificate, semantic-equivalence proof, runtime
trace, maintained architecture source of truth, employee score, complete
polyglot model, generated source rewrite, adopted patch, executed test, or
review-pass artifact.
